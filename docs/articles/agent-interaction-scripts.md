# 与 AI 对话的十种姿势 — i-rs 日常工具的智能体交互话术

## 当 CLI 工具学会"听话"

AI 终端助理和传统 CLI 最大的区别在于：**你不用记住任何命令**。

你只需要说"我今天心情不错"，AI 就会自动调用 `i-rs-mood` 记录一条心情；你说"下午坐了太久"，AI 就会调用 `i-rs-sit` 帮你记上一笔。

但这背后有一个问题：**AI 应该怎么问，才能让交互既自然又高效？**

本文整理了 i-rs 生态中最常用的 10 个工具，为每个工具设计了完整的智能体交互话术——从用户意图识别、参数询问、到结果呈现和后续建议。无论你是 AI Agent 开发者，还是想在自己的应用里集成这些 CLI 工具，都能从中找到参考。

## 1. i-rs-kv — 随手记，随时取

最通用的工具。用户想存任何键值对数据时，它都是第一选择。

### 场景：记住某个配置项

```
用户: 帮我把 API 地址记下来，https://api.example.com

AI: 好的，我用什么作为键名来存这个地址？比如 "api_url" 或者 "api_base_url"？

用户: 就叫 api_url 吧

AI: ✓ API 地址已保存 (key: api_url)
    需要的话可以随时用 `i-rs-kv get api_url` 查看
    或者通过 `i-rs-kv list` 查看所有保存的键值
```

### 场景：查找之前存的信息

```
用户: 我之前存的那个 API 地址是什么来着？

AI: 让我查一下...
    Key: api_url
    Value: https://api.example.com
    创建时间: 2026-01-15

    还有其他需要查的吗？
```

### 场景：整理存储的数据

```
用户: 帮我看看我都存了什么东西

AI: 以下是你的所有键值记录 (共 5 条)：
    KV            VALUE          TAGS
    api_url       https://...    config
    db_password   ****           secret
    username      admin          config
    theme         dark           preference
    timezone      Asia/Shanghai  preference

    要用标签过滤的话，可以试试 `i-rs-kv list --tag config`
    要搜索特定内容，用 `i-rs-kv search xxx`
```

**交互要点**: kv 的 key 需要用户命名，AI 应主动提供建议名；value 可能是敏感信息，输出的注意点要提前考虑。

## 2. i-rs-weight — 体重记录与趋势

健康管理中最基础也最持久的需求。

### 场景：记录体重

```
用户: 今天体重 71.2

AI: ✓ 已记录体重 71.2 kg (2026-05-20)
    相比上次记录 (71.5 kg) 下降了 0.3 kg 📉

    要继续坚持吗？需要我定期提醒你记录吗？
```

### 场景：查看体重趋势

```
用户: 最近一个月体重变化怎么样？

AI: 以下是最近 30 天的体重记录：

    日期       体重   变化   标签
    04-20     72.0   -      -
    04-27     71.5   -0.5   -
    05-04     71.8   +0.3   假期
    05-11     71.5   -0.3   -
    05-20     71.2   -0.3   运动

    📊 趋势图 (最近 30 天)：
    72.0 ┤ █
    71.8 ┤ █ █
    71.6 ┤ █ █ █
    71.4 ┤ █ █ █ █
    71.2 ┤ █ █ █ █ █
         └─────────────────

    统计数据：
    - 最高: 72.0 kg
    - 最低: 71.2 kg
    - 平均: 71.6 kg
    - 总变化: -0.8 kg (↓)

    趋势不错，继续加油 💪
```

### 场景：补充详细信息

```
用户: 今天早上空腹称的，运动后

AI: 你想把这些信息作为标签还是备注加上去？
    比如加 --tag 空腹 --remark "运动后"？

用户: 对，就这样

AI: ✓ 已更新记录 (71.2 kg)
    标签: 空腹
    备注: 运动后
```

**交互要点**: 体重是序列数据，AI 应主动呈现趋势而非孤立的值。对比上次记录是加分项。

## 3. i-rs-water — 饮水追踪

简单但高频，适合简短交互。

### 场景：记录喝水

```
用户: 喝了杯水，250ml

AI: ✓ 已记录 250ml (2026-05-20 14:30)
    今日累计: 750ml

    建议每日饮水量 2000ml，还差 1250ml 💧
    要继续记录其他杯数吗？
```

### 场景：查看今日饮水

```
用户: 我今天喝了多少水？

AI: 今日饮水记录：
    时间         水量
    08:30        300ml  (早餐时)
    10:00        200ml  (上午)
    14:30        250ml  (刚才)

    今日总计: 750ml / 2000ml ████░░░░░░ 37%
    还差 1250ml，加油 💪
```

**交互要点**: 饮水记录的核心价值在于"量"的累计。AI 应实时计算今日总量和目标差距，给用户直接的反馈。

## 4. i-rs-sleep — 睡眠追踪

涉及时间和质量两个维度，AI 需要主动询问缺失信息。

### 场景：记录昨晚睡眠

```
用户: 昨晚 11 点睡，今早 7 点醒

AI: 睡眠时长约 8 小时，质量如何？
    1 😴 很差 — 2 😪 较差 — 3 😌 一般 — 4 😊 不错 — 5 😁 很好

用户: 挺好的，4 分

AI: ✓ 已记录睡眠 (2026-05-19 → 2026-05-20)
    就寝: 23:00
    起床: 07:00
    时长: 8 小时 0 分
    质量: 😊 不错 (4/5)

    这个时长非常健康，继续保持！
```

### 场景：查看睡眠统计

```
用户: 最近睡眠怎么样？

AI: 睡眠统计数据：
    统计周期: 最近 7 天

    日期       就寝    起床    时长    质量
    05-14     23:30   06:30   7h      😌 3
    05-15     00:00   06:00   6h      😪 2
    05-16     22:30   07:00   8.5h    😊 4
    05-17     23:00   06:30   7.5h    😊 4
    05-18     00:30   08:00   7.5h    😌 3
    05-19     23:00   07:00   8h      😊 4
    05-20     23:30   06:30   7h      😊 4

    平均时长: 7.4 小时
    平均质量: 3.4/5
    最佳: 05-16 (8.5 小时)
    最差: 05-15 (6 小时)

    建议：最近几天的睡眠质量在提升，但入睡时间偏晚，
    如果能保持在 23:00 前入睡会更好。
```

**交互要点**: 睡眠的"质量"是个主观值，AI 必须主动询问。统计时自动计算时长和平均质量是关键价值。

## 5. i-rs-meal — 饮食记录

涉及餐别、食物、热量等多个维度，适合有结构的对话。

### 场景：记录一餐

```
用户: 中午吃了沙拉和三文鱼

AI: 好的，这是午餐还是别的什么餐别？
    可选: breakfast / lunch / dinner / snack

用户: 午餐

AI: 大约多少卡路里？不知道的话可以跳过。

用户: 大概 400 吧

AI: ✓ 已记录午餐
    食物: 沙拉, 三文鱼
    热量: ~400 kcal
    日期: 2026-05-20

    今日饮食概览：
    - 午餐: 沙拉 + 三文鱼 (400 kcal)

    要记录其他餐吗？
```

### 场景：查看今日饮食

```
用户: 我今天吃了什么？

AI: 今日饮食记录：

    餐别     食物                       热量
    早餐     燕麦粥 + 蓝莓               ~250
    午餐     沙拉 + 三文鱼               ~400
    晚餐     -                          -

    今日总计: ~650 kcal

    还缺晚餐记录，晚上吃了什么记得告诉我 😊
```

**交互要点**: 餐别有固定枚举值，AI 应主动提示选项。热量可选，不必强求。跨餐汇总让用户有全局感。

## 6. i-rs-pig — 零食冲动记录

有趣的名字背后是真实的健康需求。

### 场景：记录一次放纵

```
用户: 没忍住吃了块巧克力

AI: 😄 偶尔放松一下没问题！
    ✓ 已记录: 巧克力
    日期: 2026-05-20

    要不要加个标签，比如 "下午茶" 或者 "压力"，
    帮你以后分析是什么时候容易想吃零食？

用户: 加个 "下午" 吧

AI: ✓ 已更新记录 (巧克力 +标签:下午)
```

### 场景：查看零食模式

```
用户: 我最近吃零食多吗？

AI: 最近 7 天的记录：
    日期       食物          标签
    05-15     薯片           晚上
    05-17     奶茶           下午
    05-19     饼干           工作
    05-20     巧克力         下午

    趋势: 本周 4 次，相比上周 (2 次) 有所增加
    高频时段: 下午 (2 次)
    常见场景: 零食多出现在下午和工作间隙

    如果觉得太多，或许可以准备些健康替代品？
```

**交互要点**: 这个工具自带轻松调性，AI 可以用更口语化的语气。模式分析——时段、场景——比单纯计数更有价值。

## 8. i-rs-sit — 久坐提醒

简单的数字记录，但结合健康建议更有价值。

### 场景：记录久坐

```
用户: 坐了 2 个小时了

AI: ✓ 已记录久坐 120 分钟 (2026-05-20 15:30)
    🪑 需要站起来活动一下吗？久坐超过 1 小时建议走动几分钟。

    要不要加个标签，比如 "工作" 或者 "开会"？

用户: 加个 "开会"

AI: ✓ 已更新 (120 分钟 +标签:开会)
```

### 场景：查看久坐情况

```
用户: 我今天坐了多久？

AI: 今日久坐记录：
    时间         时长     标签
    10:00-12:00  120分    工作
    14:00-15:30  90分     工作
    15:30        120分    开会

    今日累计: 330 分钟 (5.5 小时)
    建议每日累计久坐不超过 4 小时，今天已经超了 ⏰
    记得每隔 45-60 分钟站起来活动一下！
```

**交互要点**: 久坐数据本身单一，但结合健康建议就更有价值。累计时长和超标提醒是关键功能。

## 9. i-rs-spark — 灵感捕捉

随时迸发的创意需要最快的记录路径。

### 场景：捕捉灵感

```
用户: 突然想到一个 App 创意！

AI: 记下来！是什么创意？

用户: 一个用 AI 分析饮食照片来估算卡路里的 App

AI: ✓ 灵感已捕捉 ✨ (2026-05-20 15:35)
    "一个用 AI 分析饮食照片来估算卡路里的 App"

    灵感来源是什么？比如 dream、book、conversation，或者直接跳过也行。

用户: 吃饭的时候想到的，来源 conversation 吧

AI: ✓ 已更新来源: conversation
    需要加标签分类吗？比如 "app-idea"、"health-tech" 之类的？

用户: 加个 "app-idea"

AI: ✓ 已更新 (灵感已保存)
    以后忘了可以随时 `i-rs-spark list` 回顾你的创意库 💡
```

### 场景：回顾灵感

```
用户: 我之前记过什么 App 创意吗？

AI: 以下是标签为 "app-idea" 的灵感记录：

    ID       日期     灵感                          来源
    abc123   05-20   AI 分析饮食照片估算卡路里     conversation
    def456   05-15   宠物情绪识别 App               dream
    ghi789   05-10   命令行记账工具                   book

    共 3 条灵感。要不要看看某一条的详细内容？
```

**交互要点**: 灵感捕捉的核心是"快"——用户可能随时想起，AI 要主动引导记录。来源和标签是可选项，但能帮用户日后分类检索。

## 10. i-rs-todo — 待办事项

最经典的生产力工具，强调状态流转。

### 场景：添加任务

```
用户: 帮我记一下，周五之前要提交周报

AI: ✓ 已添加待办: "提交周报"
    优先级？(高/中/低)

用户: 高

AI: ✓ 已添加 (优先级: 🔴 高)
    截止: 周五 (2026-05-22)
    还有其他任务要记吗？
```

### 场景：查看和管理任务

```
用户: 我今天有哪些事要做？

AI: 今日待办 (3 项):

    任务          优先级  标签
    🔴 提交周报   高       工作
    🟡 健身        中       健康
    🟢 买牛奶      低       生活

    完成情况: 0/3

    要不要先把 "买牛奶" 标记为已完成？

用户: 对，牛奶买了

AI: ✓ "买牛奶" 已标记为完成 ✅

    当前进度: 1/3 🟩⬜⬜
    还剩 "提交周报" 和 "健身" 💪
```

### 场景：标记完成

```
用户: 周报交了

AI: ✓ "提交周报" 已标记为完成 ✅

    当前进度: 2/3 🟩🟩⬜
    还剩 "健身" 一项

    今天效率不错！👍
```

**交互要点**: todo 的核心是"状态"，AI 要主动跟踪完成情况。标记完成（done）是最常用的操作。进度可视化让用户有成就感。

## 跨工具串联 — AI 的独特价值

这些工具单独使用时各自独立，但 AI 的真正价值在于**串联**：

```
用户: 感觉今天状态不太好

AI: 要不要记录一下心情？
    你觉得今天心情怎么样？

用户: poor 吧

AI: ✓ 已记录心情: 😕 Poor (2026-05-20)
    
    我注意到你昨晚的睡眠质量是 😌 3/5，
    今天坐了 3 个小时以上，
    这些可能都会影响心情哦。

    要不要：
    1. 起来走动一下 🚶
    2. 喝杯水 💧 (今天只喝了 500ml)
    3. 或者就是需要休息一下 🛋️
    
    要我帮你记录一下喝了水或者活动了多久吗？
```

这才是 AI + CLI 的终极体验——**工具之间没有墙，AI 在中间穿针引线。**

## 小结

这 10 种话术背后有几个共同原则：

| 原则 | 说明 |
|------|------|
| **先确认，再执行** | 拿不准的参数主动问，不要猜 |
| **显示结果** | 每次操作后展示摘要，让用户确认 |
| **提供选项** | 不要问开放式问题，给列举建议 |
| **上下文感知** | 关联其他工具的数据，提供 deeper insight |
| **主动建议** | 记录完成后给出下一步建议 |

这些话术不是固定的模板，而是 AI 与工具交互时的"最佳实践"模式。理解每个工具的数据模型和 CLI 参数后，AI 应该能灵活变通。

更重要的是——这份话术不是写给人看的，而是写给 AI 看的。当你把这份文档作为系统提示词的一部分注入 AI Agent，它就能在交互中自然遵循这些模式，让用户感觉"这个 AI 真的很懂我"。

而这，正是 i-rs 生态 + AI 智能体结合的终极形态。
